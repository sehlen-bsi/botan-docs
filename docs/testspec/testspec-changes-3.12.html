Botan 3.12 Test Suite Changes — Testspec Review

Review companion for the test specification update: changes in Botan’s test suite between release 3.11.0 and 3.12.0 (including the 3.11.1 span) that are relevant to the test specification (docs/testspec/src/*.rst, branch release-3.12-update). For each change area this page shows the new/changed test code as of tag 3.12.0 with a GitHub source link, followed by the testspec section covering the change with a link to the document on GitHub. Document excerpts reflect the working state of the concurrently updated testspec on 2026-08-11. Part II (sections 14–23, added 2026-08-18) additionally covers test-suite changes made between Botan 3.7.1 and 3.11.0 that were found — during a full verification of the test specification against Botan 3.12.0 — to not yet be reflected in the test specification.

1. Block ciphers — “Iterations” mechanism removed

The block cipher KAT driver in src/tests/test_block.cpp no longer supports the Iterations test-vector key (which repeatedly re-encrypted a vector): the Text_Based_Test constructor changed to Text_Based_Test("block", "Key,In,Out", "Tweak"), so every KAT vector is now encrypted and decrypted exactly once. The only vector using Iterations was removed from src/tests/data/block/sm4.vec.

2. X.509 IPv6 name constraints (GH #5534, #5537)

Botan 3.12.0 adds IPv6 support to name constraint processing. Three new tests were added in src/tests/test_name_constraint.cpp: Name_Constraint_IPv6_Chain_Tests (registration x509_name_constraint_ipv6_chains) validating chains against IPv6 and mixed IPv4/IPv6 constraints with data in src/tests/data/x509/name_constraint_ipv6/, Name_Constraint_IP_Mask_Tests (registration x509_name_constraint_ip_mask) driving GeneralName iPAddress DER decoding with src/tests/data/x509/general_name_ip.vec, and Name_Constraint_Empty_Subject_Test (registration x509_name_constraint_empty_subject) with data in src/tests/data/x509/name_constraint_empty_subject/.

3. X.509 path building DFS

Botan 3.12.0 reworked certificate path building into an incremental depth-first search. The new Path_Building_Tests class (registration x509_path_building) in src/tests/test_x509_path.cpp validates seven end-entity certificates against a root and two levels of seven intermediate certificates each (data in src/tests/data/x509/path_building/), checking each validation result against expected.txt.

4. CVE-2026-35580 regression test

A new regression test CVE_2026_35580_Test (registration x509_cve_2026_35580) in src/tests/test_x509_path.cpp validates an end-entity certificate from src/tests/data/x509/cve_2026_35580/ against the accompanying root certificate and asserts that path validation fails with “Cannot establish trust”.

5. OCSP: byKey ResponderID and partial stapling

Two new tests in src/tests/test_ocsp.cpp: test_response_with_bykey_responder_id parses an OCSP response identifying the responder via the byKey ResponderID choice (data: src/tests/data/x509/ocsp/byKey_responderID.der, byKey_responder.pem), and test_partial_stapling_preserves_per_slot_gap verifies that PKIX::check_ocsp keeps an empty status entry exactly at the slot of a certificate without a stapled response, preserving the per-slot gap for the online fallback.

6. X.509 unit test additions

Three additions in src/tests/unit_x509.cpp: a negative test that decoding an extension block with a duplicated extension OID throws Decoding_Error (“X509 Extensions reject duplicate OID”), test_crl_issuing_distribution_point_extension checking that the distributionPoint URI of a CRL’s IssuingDistributionPoint extension is decoded correctly, and test_crl_entry_negative_serial checking that CRL entry serial numbers encoded as negative two’s-complement INTEGERs are decoded to their magnitude.

7. TLS: RFC 9258 PSK import and TLS 1.2 no_renegotiation alert

Two new tests in src/tests/test_tls.cpp: TLS13_PSK_Import_Tests (registration tls13_psk_import) is a test vector based test of the RFC 9258 external PSK import interface using the new vector file src/tests/data/tls_13_psk_import.vec. Test_TLS12_NoRenegotiation_During_Initial_Handshake (registration tls12_no_renegotiation_during_initial_handshake) verifies that a no_renegotiation warning alert received during the initial TLS 1.2 handshake is delivered to the application but does not tear down the pending handshake state: the client must neither become active nor closed, and renegotiate(), used as a probe, must not throw (NoRenegotiation only tears down a pending state if there is already an active state).

8. TLS policy: require_extended_master_secret

src/tests/unit_tls_policy.cpp gained test_require_extended_master_secret: the default policy and the default text policy must require the extended master secret extension (RFC 7627), and a text policy override must be able to disable and re-enable the requirement.

9. TLS handshake-test hardening (explicit completion assertion)

The handshake test harness in src/tests/unit_tls.cpp previously swallowed exceptions raised during received_data(), so a handshake aborting via exception could still be reported as a success. A new member m_expect_handshake_completion (default true) now drives an explicit end-of-test assertion that both client and server reached is_active(); tests that intentionally drive a handshake abort call expect_handshake_failure() (e.g. lines 1000 and 1022) to suppress it.

10. Generic public-key verification/decryption test changes

src/tests/test_pubkey.cpp: the new helper generate_specific_false_signatures() produces deterministic invalid signatures (empty, 1-byte, 2-byte, truncated by one byte, first bit flipped); check_invalid_signatures() now runs 24 (long) / 9 (short) iterations instead of 20/5 and, after every rejected signature, re-verifies that the valid signature still verifies — regression coverage for the 3.11.1 Ed25519/ECDSA verifier-state fixes (GH #5454, #5455). check_invalid_ciphertexts() additionally verifies that the decryptor can still decrypt the original ciphertext after processing corrupted ones.

11. ECDH: negative test for off-curve peer public point

ECDH_AllGroups_Tests (registration ecdh_all_groups) in src/tests/test_ecdh.cpp gained a negative test: performing key agreement with a peer public point that is not on the curve (the encoded generator with a corrupted coordinate byte) must throw Decoding_Error; likewise the point-at-infinity as public value is rejected.

12. Certificate store: contains() cross-checks

src/tests/test_certstor_system.cpp now cross-checks certstore.contains() on all certificates returned by the find operations (lines 165, 194, 246 and 300): every certificate returned by find_all_certs()/find_cert() variants must also be reported as contained in the store.

13. Cipher modes / AEAD and CTR test vectors

Cipher_Mode_Tests in src/tests/test_modes.cpp now additionally exercises finish() and update()+finish() with a non-zero buffer offset (random 1–32 byte prefix that must remain untouched). src/tests/data/aead/gcm.vec gained new KATs with larger inputs (≈ 1 KiB, generated with OpenSSL 3.6), added together with the AVX2 CTR code path introduced in Botan 3.11.1 (GH #5474), and src/tests/data/stream/ctr.vec gained long multi-block vectors (up to 8 KiB) plus a #test cpuid avx2 directive covering the new SIMD CTR paths. Long hex lines in the vector file snippets below are truncated for display; follow the GitHub links for the full data.

Part II — Test-suite changes between Botan 3.7.1 and 3.11.0 not yet reflected in the testspec

The sections in this part document changes to Botan’s test suite that were made between releases 3.7.1 and 3.11.0 — i.e. before the 3.11.0 → 3.12.0 span covered by part I — and that a full verification of the test specification against Botan 3.12.0 found to not yet be reflected in the test specification. For each change the affected test code or test data is shown as of tag 3.12.0, followed by the testspec passage that still reflects the pre-change state. Each section summary names the commit subject, the GitHub pull request, and the first release tag containing the change.

14. Long-input block cipher KATs (GH #4649, #5339)

The AES known answer test vectors were extended with long-input KATs in two steps: commit “Fix AES test” (GH #4649, first released in Botan 3.8.0) added one 1152-bit (9-block) input per key size to cover the AVX2/VAES implementation, and commit “Add long input test vectors for various block ciphers” (GH #5339, first released in Botan 3.11.0) added one 8576-bit input per key size (the latter commit also extended aria.vec, blowfish.vec, camellia.vec, des.vec and seed.vec). All six new AES vectors are marked “# Generated by OpenSSL”; src/tests/data/block/aes.vec thereby grew from 1347 to 1353 vectors (AES-128: 385, AES-192: 452, AES-256: 516). The testspec still states “Number of test cases: 1350” and lists only 128-bit and 1024-bit In/Out lengths for AES-128, so neither the current vector count nor the new 1152-bit and 8576-bit input lengths are reflected.

15. Additional long GCM test vectors (GH #5273)

Commit “Add a couple of longer GCM test cases generated by OpenSSL” (GH #5273, first released in Botan 3.11.0) added two long test cases to src/tests/data/aead/gcm.vec: a 565-byte-input vector in the [AES-128/GCM] section and a second vector appended at the end of the file, which thereby lands in the [SM4/GCM] section. The testspec’s GCM constraint list (“Number of test cases: 43”) matched the 43 AES-GCM vectors of Botan 3.7.1 exactly; at tag 3.12.0 the file holds 47 AES-GCM vectors (55 in total, together with the vectors added in Botan 3.11.1, cf. section 13), so the count and the In/Out lengths in the constraint list are outdated.

16. GMAC test vector expansion (GH #5257, #5418)

src/tests/data/mac/gmac.vec grew from 15 to 143 vectors: commit “Add more test vectors for GMAC” (GH #5257, first released in Botan 3.11.0) appended a large set of new vectors marked “# Generated by OpenSSL” (totals now AES-128: 135, AES-192: 4, AES-256: 4; inputs up to 624 bytes), and commit “Add AVX-512 CLMUL GHASH” (GH #5418, also first released in Botan 3.11.0) extended the #test cpuid directive by avx512_clmul so the vectors also exercise the new AVX-512 CLMUL GHASH implementation. The testspec’s GMAC constraint list — 15 test cases, generated with BouncyCastle, inputs 0–400 bits — matched Botan 3.7.1 exactly, so this is pure post-3.7.1 drift; count, source and input lengths are outdated.

17. CMAC(ARIA-128) test vector (GH #5440)

Commit “Add ARIA implementation using AVX-512 GFNI” (GH #5440, first released in Botan 3.11.0) appended a [CMAC(ARIA-128)] section with one Wycheproof-derived vector to src/tests/data/mac/cmac.vec (lines 158–162); the file now holds 39 vectors. The testspec still states 36 test cases with block ciphers AES-128/192/256 only — that count corresponds to the AES-only vectors that were present at Botan 3.7.1 (the [CMAC(Blowfish)] and [CMAC(Threefish-512)] vectors predate 3.7.1) — so the new ARIA vector is not reflected.

18. SHA-1/SHA-256 vectors for new SIMD implementations (GH #4852, #4818)

Commit “Add SHA-1 using AVX2 for message expansion plus BMI2” (GH #4852, first released in Botan 3.9.0) added two vectors with 211-byte (1688-bit) and 531-byte (4248-bit) inputs to src/tests/data/hash/sha1.vec, growing it from 78 to 80 vectors, and commit “New SHA-256 using AVX2 for message expansion” (GH #4818, first released in Botan 3.8.0) added one SHA-256 vector with a 511-byte input to src/tests/data/hash/sha2_32.vec (the [SHA-256] section now holds 392 vectors); both commits also extended the #test cpuid directives to cover the new SIMD code paths. The testspec’s SHA-1 constraint list still states 76 test cases with an input range of 8–536 bits (plus the 8232-bit extreme value), so neither the count nor the new long inputs are reflected.

19. BLAKE2b test vectors replaced (GH #4748)

Commit “Replace the BLAKE2b test vectors” (GH #4748, first released in Botan 3.8.0) replaced the contents of src/tests/data/hash/blake2b.vec entirely: the [BLAKE2b(224)] section was dropped, and the new libsodium-generated set holds 257 vectors each for BLAKE2b(256), BLAKE2b(384) and BLAKE2b(512) (771 in total) with input lengths 0–256 bytes. The testspec still lists 224 bits among the output lengths and an input range of 0–255 bytes, and the example test case HASH-BLAKE2B-384 quotes an input vector (In = 0xd8dc8fdefbdce9d44e4cbafe78447bae3b5436102a, 168 bits) that no longer exists in the vector file.

20. Default entropy source list hardcoded (GH #4639)

Commit “Remove most toggles from build.h” (GH #4639, first released in Botan 3.8.0) removed the build-time configuration macro BOTAN_ENTROPY_DEFAULT_SOURCES; the default entropy source list {"rdseed", "hwrng", "getentropy", "system_rng", "system_stats"} is now hardcoded in Entropy_Sources::global_sources() in src/lib/entropy/entropy_srcs.cpp. The testspec still describes the tested entropy sources via the removed macro and additionally lists a Botan-2-era default source list (“rdseed”, “rdrand”, “darwin_secrandom”, “dev_random”, “win32_cryptoapi”, “proc_walk”, “system_stats”) that matches neither Botan 3.7.1 nor 3.12.0.

21. Certificate store: search by issuer DN and serial number (GH #5072)

Commit “Extend Certificate_Store interface to support searching by issuer DN and serial number” (GH #5072, first released in Botan 3.10.0) added find_cert_by_issuer_dn_and_serial_number() to the Certificate_Store interface. The in-memory certificate store test in src/tests/test_certstor.cpp was renamed from test_certstor_find_hash_subject to test_certstor_all_finders (lines 268–320 at tag 3.12.0) and now additionally retrieves every certificate by issuer DN and serial number, and src/tests/test_certstor_system.cpp gained the corresponding test find_cert_by_issuer_dn_and_serial_number (lines 233–253). The testspec’s CERTSTOR-SCH-1 (02_cert_store.rst) still describes only the search by the hashed subject DN; the new search operation is not covered.

22. ECDSA chosen-key verification forgery regression vectors (GH #5412)

Commit “Fix ECDSA chosen-key verification forgery” (merged via GH #5412, fixing the issue reported in GH #5211; first released in Botan 3.11.0) added 16 negative test vectors to src/tests/data/pubkey/ecdsa_verify.vec, growing it from 15 to 31 entries. These are security-relevant regression tests: signatures crafted for a chosen public key that must not verify, for the curves reported in GH #5211 (secp160k1, secp224k1) and further affected curves. The testspec’s ECDSA constraint list (4156 test cases; curves secp224r1/secp256r1/secp384r1; signature lengths 448–568 bits), which references ecdsa_verify.vec among the vector files, does not reflect these additions.

23. TLS ASIO stream: handshake-failure scenario (GH #3795)

Commit “FIX: alert handling during handshake” (GH #3795, first released in Botan 3.3.0) added the scenarios Test_Handshake_Failure and Test_Handshake_Failure_Sync to the TLS ASIO stream integration test in src/tests/test_tls_stream_integration.cpp. Together with Test_Conversation_With_Move (GH #2655, first released in Botan 3.0.0) the suite now runs eleven test cases per configuration. The testspec (16_tls.rst) still describes the suite as “four tests whereas each of them are executed in both asynchronous and synchronous ways, so as a result eight test cases exist”.
