Security and Vulnerabilities
============================

The security issues that were identified between |botan_git_base_ref| and
|botan_version| are listed in the following table.

.. list-table::
   :class: longtable
   :widths: 10 20 10 50
   :header-rows: 1

   * - Security Issue
     - Affected versions
     - Fixed in Version
     - Description
   * - CVE-2026-44378
     - All versions prior to 3.12.0
     - 3.12.0
     - Certain patterns of indefinite length encodings in BER data cause quadratic
       run time in the decoder. Such encodings were also accepted in structures that
       are required to be DER encoded, so any party able to submit ASN.1 data, for
       instance a certificate or an OCSP response, could cause a CPU based denial of
       service. The decoder bugs are fixed in
       `#5545 <https://github.com/randombit/botan/pull/5545>`_. Strict DER decoding
       of PKIX structures introduced in `#5514 <https://github.com/randombit/botan/pull/5514>`_
       and `#5521 <https://github.com/randombit/botan/pull/5521>`_ removes the exposure
       of the certificate and OCSP code paths to non-canonical encodings.
       (generated by Fable 5.1 based on Botan's security advisory and its own
       analysis of the git history)
   * - `#5523 <https://github.com/randombit/botan/pull/5523>`_,
       `#5550 <https://github.com/randombit/botan/pull/5550>`_
     - All versions prior to 3.12.0
     - 3.12.0
     - Neither the TLS 1.2 nor the TLS 1.3 client verified that the ALPN protocol
       selected by the server was among the protocols offered by the client. A
       malicious server could thus steer a client into an application protocol it
       never offered, weakening the protection against cross-protocol attacks
       (ALPACA) that ALPN is meant to provide. #5523 fixes the client side, #5550
       adds the symmetric check that the protocol selected by the server
       application callback was offered by the client. No CVE was assigned.
       (generated by Fable 5.1 based on the analysis from the appendix on #5523)
   * - `#5562 <https://github.com/randombit/botan/pull/5562>`_
     - All versions prior to 3.12.0
     - 3.12.0
     - OCSP hardening: responses carrying unknown critical extensions are now
       rejected, ``anyExtendedKeyUsage`` is no longer accepted as authorization for
       OCSP signing, the path validation restrictions are applied to the
       verification of the OCSP response signature, and a response that fails to
       parse is treated like an absent OCSP server rather than a valid one.
       No CVE was assigned. (generated by Fable 5.1 based on the commit messages
       of the PR)
   * - `#5568 <https://github.com/randombit/botan/pull/5568>`_
     - All versions prior to 3.12.0
     - 3.12.0
     - TLS sessions are no longer resumed across different SNI host names, which
       previously allowed a session established with one virtual host to be resumed
       with another. Further hardening of the TLS 1.2 server ciphersuite selection
       and additional state checks in the TLS 1.3 key update and ticket handling.
       No CVE was assigned. (generated by Fable 5.1 based on the commit messages
       of the PR)
   * - `#5550 <https://github.com/randombit/botan/pull/5550>`_
     - All versions prior to 3.12.0
     - 3.12.0
     - Large set of TLS hardening fixes, among them: detection of the TLS 1.3
       downgrade marker in ServerHello, rejection of compressed ECDH key shares,
       constant-time removal of TLS 1.3 record padding and constant-time DTLS cookie
       comparison, the TLS 1.2 client verifying that a resumed session uses the same
       ciphersuite, aligned key usage constraints for client certificates in TLS 1.2
       and 1.3, and tightened length and decode-time checks across all TLS message
       and extension parsers. No CVE was assigned. (generated by Fable 5.1 based on
       the commit messages of the PR)
   * - CVE-2026-34580
     - Regarding general certification path validation only 3.11 is affected. Regarding certificate matching in a certificate store, the issue affects earlier versions as well. Earliest affected version is not known.
     - 3.11.1
     - The certificate store's function to search for a given certificate within the store returns any certificate whose SubjectDN matches that of the sought certificate.
   * - CVE-2026-34582
     - Earliest affected version is unknown
     - 3.11.1
     - TLS 1.3 client authentication can be trivially bypassed.
   * - `#5454 <https://github.com/randombit/botan/pull/5454>`_, `#5455 <https://github.com/randombit/botan/pull/5455>`_
     - Earliest affected version is unknown
     - 3.11.1
     - The verification operation class of EdDSA and ECDSA handles the case of a too short signature in an erroneous manner. This leads to the verification object remaining in a state with an already non-empty hashed message after a failed
       signature verification. While the
       caller assumes that a new verification is started, the verification operation instance appends the new message for verification to the previous one. This allows attacks where the attacker first deliberately causes a failed
       verification for some prefix A. In the second step he submits the message B together with a valid signature for the message A || B. The verification of B succeeds due to the pending message in the internal hash context, even though
       the legitimate signer only signed A || B, and never signed B.
   * - `#5614 <https://github.com/randombit/botan/issues/5614>`_
     - up to 3.11.0 and presumably also 3.12.0
     -
     - Problematic behaviour of `Stateful_RNG::force_reseed()` with respect to the resulting RNG state with possible side effects to SCA countermeasures in ECC operations.
   * - `#5615 <https://github.com/randombit/botan/issues/5615>`_
     - up to 3.11.0 and presumably also 3.12.0
     -
     - Control of SCA countermeasures in ECC operations depends implicitly on RNG seeding state. This is an obscure and error prone mechanism to control an important security measure.


Security Issues Published after the Release of |botan_version|
--------------------------------------------------------------

Botan's security advisories are maintained at
`https://botan.randombit.net/security.html <https://botan.randombit.net/security.html>`_.
At the time of writing, the advisories published after the release of
|botan_version| list seven issues fixed in 3.13.0 which also affect
|botan_version|, among them CVE-2026-48057 (bypass of the name constraints
enforcement for distinguished names), a blind SSRF via OCSP redirect
following, and a reinitialization of ``AutoSeeded_RNG`` from predictable data
after clearing its state. These issues are outside the scope of the present
audit and will be covered by the audit of the subsequent release.
(paragraph generated by Fable 5.1 based on Botan's security advisory file at tag 3.13.0)

     - All earlier versions featuring ML-DSA
     - Fix is pending. PR exists (#5307).
     - RFC 9881 specifies three alternative encodings of the ML-DSA private key. Botan still reads and writes the "pure seed" format, which is not compatible to any of those specified in RFC 9881.
